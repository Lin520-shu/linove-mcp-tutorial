# 电脑关机，你的 AI 也能接着跑

用一台 VPS 加一个域名，给 MCP 服务一个固定的公网入口。

成本低，部署简单，网络安全性高，一份能照着做的系统化教程，外加我踩过的所有坑。

## 你需要什么

- 一台轻量应用服务器 VPS，1 核 2G 够用
- 一个域名，.xyz 首年十几块
- 一个 Cloudflare 免费账号

## 你能得到什么

- 一个 24 小时在线的 MCP 服务地址，手机断电、电脑关机都不影响
- 一条挂在 Cloudflare 后面的稳定入口
- 一套学会就能反复用的部署流程

## 建议搭配

记忆系统、自主唤醒、支持远程 MCP 的前端。

## 本篇介绍

把服务放到一台云服务器上，再挂个域名，它就有了固定地址，任何支持远程 MCP 的客户端都能连进来，前端想换哪个换哪个。

## 总成本

115 元。一年 VPS 加一年域名，再加本次跑模型的 Token 费。

---

## 第一步，VPS 装 Docker

拉取你需要的业务镜像，比如各类 MCP 服务或记忆系统，配置用 env 文件喂。

这里有一条死线：换 key 可以，换模型不行。向量模型一换维度就变，bge-m3 是 1024 维，库里所有向量当场作废，搜索出来全是垃圾。认准这个别动。

## 第二步，安全隔离

容器只绑本机 127.0.0.1:18001，不要往公网暴露。

防火墙只开你 ssh 实际用的那个端口和 443，一定要按自己机器的实际端口来填，填错就把自己关在门外。80 端口尽量别碰，不少机器的 sshd 就占着 80，你去抢会直接断线。

## 第三步，Nginx 反代

Nginx 在 443 上做反向代理转给 18001，证书用自签的，openssl 一条命令生成，十年有效期。

自签证书单独用会报警告，但前面有 Cloudflare 兜着就没事，前提是 CF 的 SSL 模式设成完全，不是完全严格。

## 第四步，域名解析

域名 NS 切到 Cloudflare，加一条 A 记录指向 VPS 公网 IP，开橙云代理。生效要等，几十分钟到几小时都有可能。

想确认到底通没通，用 curl 加 --resolve 你的域名:443:你的IP 直接指 IP 去请求，能把 DNS 还没生效和服务本身坏了分开，这一步能省很多时间。

```bash
curl -s -o /dev/null -w "%{http_code}\n" --resolve example.com:443:你的IP https://example.com/mcp
```

## 第五步，客户端连接

客户端里加远程 MCP，地址填 https://你的域名/mcp，认证头写 Authorization 加 Bearer 加你的 token。

这一步最容易翻车：很多客户端要求 headers 是 JSON 对象，你要是把它写成一整串字符串，它不报错，直接把这条服务当成不存在，你在界面里翻半天也找不到。

```json
{
  "url": "https://example.com/mcp",
  "headers": {
    "Authorization": "Bearer 你的token"
  }
}
```

## 怎么验证

不带 token 请求应该回 401。401 是好事，说明门在、要钥匙。

带上 token 做一次 initialize 握手，回来 200 并且自报服务名，才算真通。

要是回 502 或者 504，那是反代后面根本没人，回到第一步看容器活没活。

## 三个我踩过的坑

1. headers 存成字符串，静默失效，我查了三个小时。
2. env 和 config 两层都得改对，改完 env 必须重建容器，简单重启读不到新值。
3. 80 端口不能碰。

## 最后一句

token 别截图，别发群里，谁拿到谁就能读走你全部的记录。
